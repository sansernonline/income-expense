## 2 รอบที่ศูนย์ (ครั้งเดียว)
สร้าง docs/BUILD-PLAN.md ตามแม่แบบของ spec-to-code-loop: หนึ่งแถวต่อหนึ่งข้อกำหนด (FR/NFR/BR) ที่ใช้งาน คอลัมน์ รหัส · สิ่งที่ต้องได้ · ไฟล์ที่จะแตะ · TC ที่ผูก (จากตาราง Traceability ท้ายไฟล์ test case) · สถานะ · หลักฐาน
บนสุดเขียนบรรทัด "ลำดับเอกสาร" ตามข้างบน
แอปมีโค้ดอยู่แล้ว ดังนั้นก่อนตั้งสถานะ ให้ลองรัน test ที่ครอบข้อนั้นก่อน: ผ่านและมีหลักฐานจึงลง "เสร็จ" ที่เหลือ "ค้างอยู่"
ตรวจแผน 5 ข้อ (ครบ · ขนาด · ชื่อตรงกัน · เคสที่กัด · สัดส่วน) แล้วทำต่อได้เลย ไม่ต้องหยุดรอ (เจ้าของงานตรวจตอนจบ)

## 3 วงรอบต่อหนึ่งข้อ (ห้ามรวบหลายข้อ)
1. หยิบแถวแรกที่ยัง "ค้างอยู่" ตามลำดับ P1→P2→P3
2. เขียน test ก่อน ชื่อ test มีรหัสข้อกำหนด เช่น FR_SET_100 · ผลคาดหวังคิดมือจากข้อกำหนดก่อนเปิดโค้ด (เช่น กำไร 30% รายรับ 100,000 → รายจ่าย 70,000) ห้ามลอกจากหน้าจอ
3. รันให้เห็น "แดง" จริง ข้ามไม่ได้ (ข้อที่โค้ดตรงอยู่แล้ว test จะเขียวทันที ให้ทำให้แดงชั่วคราวด้วยการทำลายพฤติกรรมนั้นสั้น ๆ เพื่อพิสูจน์ว่า test จับได้ แล้วคืนค่า)
4. เขียนโค้ดน้อยที่สุดจนเขียว แล้วรัน test ทั้งชุด
5. ข้อที่เกี่ยวหน้าจอ: เปิดแอปจริง (node server/server.js พอร์ต 3000) ถ่ายภาพที่ความกว้าง 1360 และ 390 px ลง _to_delete/check/ เทียบกับ mockup/IEGEN-mockup.html ตามเช็กลิสต์ 5 ข้อของ spec-to-code-loop รายงานความต่างเป็นรายการ
6. อัปเดตแถวใน BUILD-PLAN.md (สถานะ + ชื่อ test + ผลรัน) และหัวข้อ "สถานะล่าสุด" · ไม่ commit (ยังไม่ได้รับอนุญาต) ให้ใส่ข้อความ commit ที่แนะนำ รูปแบบ Conventional Commit ภาษาอังกฤษ ในคอลัมน์ commit พร้อม "(รอ commit)"

## 4 กฎเหล็ก
- ห้ามแก้หรือลบ test เพื่อให้ผ่าน test แดง = โค้ดผิด · จะแก้ test ได้เมื่อพิสูจน์ว่าเขียนผิดจากข้อกำหนด และต้องจดในรายงาน
- ข้อเดียวลองไม่เกิน 3 รอบ พังแล้วแตกเป็นขั้นย่อย ครบ 3 รอบลง "ติด" + เหตุผล เก็บงานเป็น _to_delete/patches/stuck-<รหัส>.patch คืนสายงานให้ test ทั้งชุดเขียว แล้วไปข้อต่อไป
- ห้าม mock สิ่งที่กำลังทดสอบ · mock เฉพาะของข้างนอก (Typhoon: stub global fetch ใน server/typhoon.test.js ครอบกรณี ไม่มีคีย์ · หมดเวลา 40 วินาที · ตอบไม่ใช่ JSON ลองซ้ำ 1 ครั้ง · สำเร็จ)
- ไม่เพิ่ม dependency ฝั่งรัน (zero dependency) · เครื่องมือทดสอบเบราว์เซอร์ใส่เป็น devDependency ได้ถ้าจำเป็นจริง และบอกในรายงาน · SheetJS ยังโหลดจาก cdnjs เวอร์ชัน 0.18.5
- ความปลอดภัย: คีย์ Typhoon อยู่ใน .env ฝั่งเซิร์ฟเวอร์เท่านั้น ห้ามส่งถึงเบราว์เซอร์/log · เซิร์ฟเวอร์ bind 127.0.0.1 · ข้อมูลจาก AI ผ่าน sanitizePlan ก่อนใช้ทุกครั้ง · ห้ามใช้ innerHTML กับข้อความผู้ใช้หรือ AI
- แก้โค้ดสร้างรายการต้องคง: ผลรวมรายรับเดือน = เป้าพอดี · รายจ่ายต่อหมวด = % × รายรับ · วันหยุดไม่มีรายรับ (ดู DECISIONS D-01)
- แก้ app.js / styles.css / index.html แล้วรัน node --check · รัน node scripts/build-mockup.js ให้ mockup ตรงโค้ดล่าสุด
- ของชั่วคราวทุกอย่างลง _to_delete/ ที่รากโปรเจกต์ · ไฟล์ใหม่ตั้งชื่อตัวพิมพ์เล็กคั่นด้วย -
- test อยู่ข้างโค้ด (*.test.js) · เพิ่มสคริปต์ "test" ใน package.json ให้รันทุกไฟล์ด้วยคำสั่งเดียว (node --test)

## 5 เงื่อนไขหยุด (รันแล้วรู้ผล)
จบเมื่อทั้งหมดนี้จริง: (ก) คำสั่ง test ทั้งชุดเขียว (ข) ทุกแถว P1 ใน BUILD-PLAN.md เป็น "เสร็จ" หรือ "ติด" ที่มีเหตุผล (ค) P2 และ P3 ไม่มี "ค้างอยู่" เหลือ ยกเว้นลงเหตุผล (ง) ตารางสืบย้อน ข้อกำหนด → test → ผลล่าสุด อยู่ท้าย BUILD-PLAN.md ข้อที่ไม่มี test บอกตรง ๆ ว่าไม่มี
อย่าหยุดก่อน แม้เหนื่อย ถ้าข้อกำหนดไหนยังไม่มีคำตอบ ให้ลงค้างอยู่แล้วทำข้ออื่น
